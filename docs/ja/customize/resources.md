# リソースとライフサイクル

複数のプレイヤーで何が共有され、何がプレイヤーごとに確保され、`destroy()` が実際に何を解放するかをまとめます。1 ページに多数のプレイヤーを置く前や、破棄まわりでリークや表示消えが起きたときに参照してください。

## 共有されるもの・プレイヤーごとのもの

| 対象 | スコープ | 補足 |
|---|---|---|
| WASM モジュールとメモリ | **ページに 1 つ** | `initialize()` はモジュールレベルのシングルトンなので、複数回呼んでも問題ありません。 |
| テクスチャ（PixiJS） | **すべての `SSPlayer` で共有** | Pixi のグローバル `Assets` キャッシュへ登録されます。キーは URL です（セルマップハッシュは 1 つの `.ssab` 内でしか一意でないため使いません）。同じアトラスを使う 2 つのプレイヤーは 1 つの GPU テクスチャを再利用します。 |
| テクスチャ（WebGL） | **Surface 内で共有** | `WebGLTexture` は生成したコンテキストに属するので、Surface が所有します。キーは URL です（セルマップハッシュは 1 つの `.ssab` 内でしか一意でないため使いません）。同じアトラスを使う 2 つのプレイヤーは 1 回のアップロードを再利用します。 |
| 埋め込みテクスチャ（`--embedded`） | **プレイヤーごと** | `.ssab` 自身のバイト列からデコードされ、意図的に共有キャッシュの外に置かれます。`destroy()` で解放されます。 |
| パース済み `.ssab`（WASM） | **URL 単位で共有** | 同じ URL から `load()` して中身が同一なら、プレイヤー間でパース済みのパックを 1 つ共有し、プレイヤーごとに持つのは再生状態だけです。`loadBuffer()` で渡したパックは URL を持たないため共有されません。同じ URL でも中身が変わったファイルも共有されません。 |
| インスタンスパック | **URL 単位で共有** | インスタンスパーツが参照するパックは兄弟の `.ssab` として取得され、同じ規則で共有されます。1 つのプレイヤーのツリー内ではパックハッシュでも重複排除されます。`InstancePackProvider` が渡したバイト列は共有されません。 |

実務上の帰結として、**同じ URL から読み込んだ同じキャラクターを N 体出しても、パース済み `.ssab` は 1 つと N 個の小さな再生状態**で済みます。テクスチャもどちらのバックエンドでも 1 セットです。`loadBuffer()` で渡したパックだけは例外で、1 体ごとにコピーを持ちます。

## 同じアニメを大量に出す場合

**1 つの Surface にまとめてください。** `SSSurface` は単一の WebGL コンテキスト上に
`SSPlayer` を何体でも載せられるので、何十体出してもコンテキストは 1 つです。

```ts
const surface = new SSSurface(canvas, { autoStart: true });
const a = surface.createPlayer();
const b = surface.createPlayer();
```

これが効くのは、ブラウザが同時に生存できる WebGL コンテキスト数を制限しているためです。上限はブラウザによっておおむね 8〜16 程度で、超えると古いコンテキストから破棄され、canvas が真っ白になる形で表面化します。**この上限はプレイヤー単位ではなく Surface 単位**なので、Surface を多数作らない限り問題になりません。

各統合はすでにこの形になっているので、普段は意識せずに済みます:

| | コンテキスト数 |
|---|---|
| `<ss-player>` 要素 | **ページに 1 つ**。既定で 1 枚のオーバーレイ canvas を共有するので、何個置いても増えません。`standalone` を付けた要素だけが自前のコンテキストを持ちます（アニメに CSS 効果を効かせたい・自前の不透明背景が要る・通常のスタッキング順に置きたいときだけ使ってください）。 |
| `ssplayer-tyranoscript` | **使用中のレイヤーごとに 1 つ**（通常 1〜2）。キャラの数では増えません。 |
| `ssplayer-rmmz` | **自前では持ちません**。RPG Maker MZ のコンテキストに描きます。 |
| `ssplayer-pixi` | **自前では持ちません**。あなたの PixiJS アプリケーションのものに描きます。 |

`ssplayer-pixi` は、ほかの PixiJS コンテンツと同じシーンに混ぜたい場合に依然として適しています。そのシーンごと描画をバッチ化でき、テクスチャも `Assets` キャッシュ経由で共有されます。

## 破棄する

`destroy()` は必ず呼んでください。冪等なので、フレームワークの後始末から念のため 2 回呼ばれても安全です。

```ts
player.destroy();
```

解放されるのは、そのプレイヤーの WASM アロケーション（ランタイムコンテキスト、`.ssab`
リソース、インスタンス／エフェクトの子スロット）、レンダラーの GPU オブジェクト、およびそのプレイヤーが所有するテクスチャです。

::: warning PixiJS: 共有テクスチャは意図的に解放しません
`destroy()` は URL から読み込んだテクスチャを **`Assets.unload()` しません**。ほかの `SSPlayer`
がまだそのテクスチャで描画している可能性があり、取り上げるとそちらの表示が消えるためです。解放されるのは、そのプレイヤーが単独で所有する埋め込み（`--embedded`）テクスチャだけです。

グローバル `Assets` キャッシュの管理はホスト側の責務です。ほかの Pixi アセットと同じように、シーンを使い終わったタイミングで自分でアンロードしてください。
:::

WASM ハンドルには最後の保険として `FinalizationRegistry` が仕掛けてありますが、GC のタイミングは規定されておらず、ファイナライザーが走らないこともあります。リーク対策の保険であって破棄手順ではないと考え、`destroy()` を呼んでください。

## WebGL のコンテキストロスト

`SSSurface` が面倒を見ます。`webglcontextlost` / `webglcontextrestored` を監視し、コンテキストが失われている間は描画を止め、復帰時には GL オブジェクトを作り直してすべてのテクスチャを再アップロードしてから再開します。テクスチャが欠けたままのフレームは描画されません。これはコンテキストを積極的に破棄するモバイル webview で特に効きます。この処理がなければ
canvas は復帰せず白いままになります。

テクスチャは保持しておいた生成情報から復元されます。URL は再フェッチ、埋め込みバイト列は再デコードです。ひとつだけ利用側の協力が要るのが、`bindTextureSource()` で自分で渡したテクスチャです。元の `TexImageSource` からそのまま再アップロードするため、そのソースを手放していると（クローズ済みの `ImageBitmap` など）その項目は警告付きでスキップされ、描画されません。

## テクスチャを自分で供給する

テクスチャは通常 `.ssab` の兄弟ファイルとして解決されます。それ以外の場所から供給したい場合（インメモリのバンドル、エンジンが既に GPU 上に持っているアトラスなど）は、
[`IResourceManager`](https://cri-middleware.github.io/SSPlayerForWeb/api/@spritestudio/ssplayer-core/interfaces/IResourceManager) を実装してコアを直接駆動するか、`loadBuffer(ssab, textures)` でパックを渡してください。第 2 引数でセルマップハッシュごとに URL・エンコード済みの画像バイト列・画像ソースのいずれかを指定でき、WebGL では `bindTextureSource()` による登録が代わりに行われます。パックを結びつける `load()` / `loadBuffer()` は最初にプレイヤーのテクスチャマネージャーをリセットするため、`load()` の前に `bindTextureSource()` で登録したテクスチャは失われます。

読み込み*後*にテクスチャを差し替えたい場合（着せ替えや動的な表情差分など）は、名前をキーにした[テクスチャ差し替え（着せ替え）](./texture-replacement.md) の API を使ってください。セルマップ名の解決を代わりに行い、元テクスチャへの復元もできます。

URL で辿れないインスタンスパックも同様で、
`player.internalPlayer.setInstancePackProvider(provider)` で、[`InstancePackProvider`](https://cri-middleware.github.io/SSPlayerForWeb/api/@spritestudio/ssplayer-core/type-aliases/InstancePackProvider) 型の関数を、パックのリソースが準備される前（`load()` / `loadBuffer()` の前）に渡します。この場合コアはフェッチを行わなくなるため、そのパックのテクスチャ登録も利用側の責務になります。
