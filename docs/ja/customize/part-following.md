# パーツトラッキング（指定パーツへの追従）

指定したパーツに、ユーザーが用意した表示オブジェクト（武器・エフェクト・当たり判定など）を毎フレーム追従させる機能です。プレイヤーはオブジェクトを生成も破棄もせず、渡されたオブジェクトを駆動するだけの連動（Constraint）方式で、ターゲットのライフサイクルはユーザーが所有します。

提供の形はレンダラごとに異なり、**全プレイヤー共通のプル API** と、シーングラフを持つプレイヤーだけの**自動追従**の 2 層構成になっています。

| プレイヤー | 追従の方法 |
|---|---|
| `SSPlayer`（PixiJS） | `attachToPart()` による自動追従 ＋ プル API |
| `SSPlayer`（RPG ツクール MZ） | `attachToPart()` による自動追従 ＋ プル API |
| `SSPlayer`（WebGL） | シーングラフを持たないため**プル API のみ**（`getPartTransform()` ＋ `onFrame()`） |

::: warning メッシュ（スキン）パーツには直接追従できません
ボーンにバインドされた**メッシュパーツ**（手・顔などの変形パーツ）は、頂点がボーンのスキニングで描かれる一方、パーツ自身の変換はセットアップ時のノード位置（多くはキャラクターのルート付近）に留まります。そのため、こうしたパーツを `attachToPart()` の追従先に指定したり `getPartTransform()` で読み出したりすると、対象は見た目の絵ではなくルート付近に吸い寄せられます。

メッシュパーツの位置に追従させたいときは、SpriteStudio 側でその位置に **NULL パーツ**（ボーンポイント／空パーツ）を 1 つ置き、そのパーツ名を追従先に指定してください。ボーン（armature）やジョイントパーツを指定しても同様に追従できます。

ボーンにバインドされていない**リジッドメッシュ**（自身のメッシュキーだけで変形するパーツ）は正しく追従します。影響を受けるのはスキンパーツだけです。判別には `isPartSkinnedMesh(part)` を使えます（追従先の候補リストで淡色表示するなど）。この判定は追従自体を妨げません。
:::

## 基本的な使い方

```ts
import { Container } from 'pixi.js';

const sword = new Container();  // ターゲットはユーザーが所有する

// "FrontHand" パーツに追従させる。既定で駆動するのは位置と回転。
// 剣は絵の一部なのでスケールも駆動する
const attachment = player.attachToPart('FrontHand', sword, { scale: true });

// 位置と回転だけ追従させ（既定）、パーツが hide のフレームではターゲットも隠す
player.attachToPart('effect_root', effect, {
  onHide: 'hide',
});

// 解除
attachment.detach();
// または
player.detachFromPart(sword);
```

## API 一覧

| メソッド | 説明 |
|---|---|
| `attachToPart(part, target, options?)` | ターゲットをパーツに追従させる。`SSPartAttachment`（`target` と `detach()` を持つハンドル）を返す。**PixiJS / MZ のみ** |
| `detachFromPart(target)` | その `target` の追従を解除する。**PixiJS / MZ のみ** |
| `getPartTransform(part, out?)` | そのパーツの現在フレームの変換行列（2D アフィン `[m00, m01, m10, m11, tx, ty]`。プレイヤーの `flipX` / `flipY` / `offsetX` / `offsetY` を適用済み）。パーツが不明なら `null` |
| `isPartHidden(part)` | そのパーツが現在フレームで hide かどうか。パーツが不明なら `null` |
| `isPartSkinnedMesh(part)` | そのパーツが**スキン（ボーンバインド）メッシュ**かどうか。追従先には不向き（上記の警告を参照）。パーツが不明なら `null` |
| `getPartQuad(part, out?)` | そのパーツを現在フレームで描いている輪郭。`getPartTransform` と同じ空間の 4 隅 `[ltx, lty, rtx, rty, lbx, lby, rbx, rby]`（[パーツの輪郭](#a-parts-outline) を参照）。パーツが不明か非表示、または自分では何も描かないパーツなら `null` |
| `hitTestPart(x, y, parts?)` | 点を含む輪郭のうち最も手前のパーツのインデックス。`parts`（名前かインデックス。省略時は全パーツ）の中から探し、無ければ `-1` |
| `onFrame(cb)` | フレームが進むたびに発火する（ワールド行列が確定した後）。解除用の関数（`Unsubscribe`）を返す |
| `findPartIndex(partName)` | パーツインデックス。現在のアニメーションに無ければ `-1` |

各メソッドの `part` は**パーツ名**と**パーツインデックス**のどちらでも渡せます（`number | string`）。

> **パーツインデックスの使い方について**: パーツインデックスは同一アセット（同じ `.ssab`）内では安定しているので、毎フレーム自前で読み出すなら `findPartIndex()` で一度パーツ名を解決して、そのインデックスを使い回すことを推奨します。

> オブジェクトを常時追従させるまでもなく「その瞬間のパーツ位置だけ知りたい」場合（弾の発射位置を取るなど）は、`attachToPart()` を使わず `getPartTransform()` を直接呼ぶ方が簡潔です。

## 追従オプション（`SSPartFollowOptions`）

| オプション | 既定 | 説明 |
|---|---|---|
| `position` | `true` | 位置を駆動する |
| `rotation` | `true` | 回転を駆動する |
| `scale` | `false` | スケールを駆動する。**既定は off** — 追従対象はパーツの位置に置くもので、パーツに大きさを決めさせるものではありません |
| `onHide` | `'follow'` | パーツが hide のフレームでの挙動。`'follow'`（追従を継続）/ `'hide'`（ターゲットも隠す） |
| `addAsChild` | `true` | ターゲットをプレイヤーの子として追加する。子にするとプレイヤー自身の変換を階層継承し、パーツと完全に一致する |

3 軸（`position` / `rotation` / `scale`）がすべて ON の場合はアフィン行列をそのまま適用するため、**反転（Flip）も含めて厳密に一致**します。一部だけ ON の場合は行列を TRS（平行移動 × 回転 × スケール）に分解して有効な軸だけを書き込み、無効な軸はターゲット自身の値を保持します。

> パーツ自身の**せん断（Skew）は追従先には乗りません**。SpriteStudio ではせん断はパーツ単位の頂点変形であり、子に伝搬しません。ランタイムはこれをパーツ自身の描画頂点に焼き込み、`getPartTransform()` が返すワールド行列には含めないため、追従はパーツのノード姿勢（せん断なし）を追います——これはそのパーツの子が継承する姿勢と同じです。（一部の軸だけを追従させるときの TRS 分解は依然として「せん断なし」を前提とします。非一様スケールの親の下で回転したパーツはアフィンにせん断が残り得るので、厳密さが必要なら 3 軸すべてを ON にするか、`getPartTransform()` の生アフィンを使ってください。）

## 反転（`flipX` / `flipY`）と組み合わせる

プレイヤーの [反転とオフセット](/ja/usage/basic#flip-and-offset) は追従と正しく噛み合います。
`getPartTransform()` が返すのは反転後のパーツの姿勢なので、**反転してもターゲットはパーツから外れません**。

3 軸すべて ON（`scale: true`）なら、アフィン行列をそのまま書き込むので**鏡像も含めて厳密に一致**します。これは裏を返すと、**ターゲット自身の絵も裏返る**ということです（鏡像は負のスケールとして届きます）。パーツに完全に一致させたいのだから通常はこれが望ましい挙動ですが、ターゲットに文字や非対称なアイコンを載せている場合は鏡文字になります。

ターゲットの絵を正立させたい場合は次のどちらかを取ってください。

- `scale: false`（既定）にする（下記のとおり `flipX` では向きに 180 度の差が残ります）
- ターゲットを 1 枚 `Container` で包み、追従させるのは外側、絵を載せるのは内側にして、内側で `scale.x = -1` を掛けて鏡像を打ち消す

3 軸すべて ON で使っているかぎり、これは `player.scale.x = -1` で反転した場合と**同じ結果**です。つまりこの場面では `flipX` の優位はありません。効いてくるのは `addAsChild: false` の方です（下記）。

> **`scale: false` にすると、`flipX` では向きに 180 度の差が残ります**（`flipY` では残りません）。鏡像は回転では表せず負のスケールとしてしか表せないため、スケールを駆動しないターゲットには鏡像が届きません。左右と上下で違うのは、`decomposePartAffine()` が鏡像を「回転 ＋ 負のスケール」に分解する際、符号を Y 軸側に載せる規約を採っているからです。左右の鏡像はこの形に直すのに余分な 180 度回転を必要とし、それが回転側に残ります。**位置は行列式によらず常に正確です。**

鏡像になるのは `flipX` / `flipY` を使ったときだけではありません。SpriteStudio 側でパーツやその親に負のスケールが付いていれば、反転していなくても鏡像です。しかも **2 つは掛け合わさるので、偶数回で打ち消し合います** — 元から反転しているパーツを `flipX` すると行列式は**正**に戻ります。「反転設定を入れたから鏡像のはず」と決め打ちせず、必要なら手元の行列の行列式を見てください。

**`addAsChild: false` こそ反転が効いてくる場面です。** 反転はプレイヤーの表示オブジェクトではなくジオメトリ側に畳み込まれているため、`getPartTransform()` が返すアフィンがそれを含んでいます。結果、プレイヤーの外に置いたターゲットも（同じ座標空間を共有している限り）追加の手当てなしで正しい位置に付いてきます。

これを `player.scale.x = -1` でやると、返るアフィンは反転を一切知りません。そのターゲットも、DOM オーバーレイも、当たり判定の座標も、プレイヤーのサブツリーの外にいるものはすべて反転前の位置に取り残されるので、ホスト側で反転を掛け直す必要があります。

## 追従のタイミングと精度

追従の駆動は、そのフレームのワールド行列が確定した後に行われます。ターゲットは**同じフレーム内**で更新されるため、1 フレーム遅れることはありません。

| プレイヤー | 駆動のタイミング |
|---|---|
| `SSPlayer`（PixiJS） | `renderFrame()` の末尾。そのフレームのメッシュを配置した**後**なので、ターゲットはアニメーションより手前に描画されます |
| `SSPlayer`（MZ） | `update()` 内、イベント配信の後 |
| `SSPlayer`（WebGL） | 自動追従はありません（`onFrame` がワールド行列の確定後に発火します） |

`getPartTransform()` が返すのは**アニメーションローカル・Y-down**（パーツが描画される空間そのもの）のアフィン変換行列です。ターゲットをどこに置くかで、一致の度合いが変わります。

- `addAsChild: true`（既定）ならターゲットはプレイヤーの子になるため、プレイヤー自身の変換を階層継承し、**パーツと完全に一致**します。
- `addAsChild: false` の場合、ターゲットは元々いる場所のまま駆動されます。一致するのは、ターゲットがプレイヤーと同じ座標空間を共有している間だけです。
- WebGL プレイヤーで DOM 要素や別 canvas を追従させる場合は、このアフィンに表示側の変換（`transformMatrix` とプロジェクション）を自前で合成する必要があります。

### 再生状態による違い

追従は再生の駆動に乗って動きます。

- **停止中（`stop()`）** — `SSPlayer`（PixiJS / MZ）は `update()` が早期 return するため、**追従も `onFrame` も止まります**。停止したまま `player.frameNo` でシークしても追従は更新されません。
- **一時停止中（`pause()`）** — `SSPlayer`（PixiJS / MZ）は追従・`onFrame` とも継続します。`SSPlayer`（WebGL）は `onFrame` を発火しません。

## 手動で追従する（プル API）

シーングラフを持たない `SSPlayer`（WebGL）や、追従先が表示オブジェクトでない場合（DOM オーバーレイ、当たり判定の座標など）は、`onFrame()` と `getPartTransform()` を組み合わせて自前で駆動します。

```ts
const affine = new Float32Array(6);   // 使い回してアロケーションを避ける

const off = player.onFrame(() => {
  const m = player.getPartTransform('FrontHand', affine);
  if (!m) return;                     // 現在のアニメーションに無いパーツ

  // m = [m00, m01, m10, m11, tx, ty]（アニメーションローカル・Y-down）
  //   x' = m00 * x + m01 * y + tx
  //   y' = m10 * x + m11 * y + ty
  myObject.position.set(m[4], m[5]);
});

off();  // 購読解除
```

`out` 引数（`Float32Array(6)`）を渡すとその配列に書き込まれ、毎フレームのアロケーションを避けられます。返る配列は WASM メモリからコピー済みなので、フレームをまたいで保持しても安全です。

位置・回転・スケールの成分が欲しい場合は、コアが公開している分解ヘルパを使えます。

```ts
import { decomposePartAffine } from '@spritestudio/ssplayer-pixi';

const { x, y, rotation, scaleX, scaleY } = decomposePartAffine(m);
```

> 反転（ミラー）したパーツでは、行列式の符号が `scaleY` に折り込まれて返ります（`scaleY` が負になります）。

## パーツの輪郭 {#a-parts-outline}

`getPartQuad()` は、パーツを描いている 4 隅（左上・右上・左下・右下）を `getPartTransform()` と同じ空間で返します。回転したパーツなら回転した四角形になります。`hitTestPart()` は点をこの輪郭で判定し、点を含む最も手前のパーツを返します。

```ts
// プレイヤー自身の空間の点。PixiJS ならポインタイベントの位置を player.toLocal() に通したもの
const index = player.hitTestPart(local.x, local.y, ['button_face']);
if (index >= 0) console.log('hit', player.getPartNames()[index]);
```

輪郭は描いた絵そのものです。セルのあるパーツは描いた 4 隅で、スキューと頂点変形を含みます。メッシュパーツは頂点を囲む軸平行の矩形で、ボーンにバインドされていても描かれる場所を囲みます。シェイプは自身の頂点を囲む矩形をパーツの変換に通したもので、頂点変形で角が外へ出ても輪郭に入ります。Null・ボーン・インスタンス・エフェクトのパーツは自分では何も描かないので輪郭がなく、非表示のパーツにもありません。アルファ 0 で描かれているパーツには輪郭があります。どちらも `getPartTransform()` と同じく最後に描いたフレームを読み、フレームを評価しません。

アニメーションをボタンにして、一部のパーツでだけポインタを受けたいときは、この 2 つを使う [UI ボタン（PixiJS）](/ja/usage/pixi-ui) を参照してください。

## 追従先パーツの選択 UI を作る

追従先パーツをユーザーに選ばせる UI を作る場合は、SpriteStudio / Unity / Godot のエディタと同じ作法に倣ってください。**全パーツを列挙しつつ、スキンメッシュパーツは選べないようにする**（誤選択を防ぐ）——ただし手打ちの名前は通す（意図的に追従させたい場合があるため）、という形です。

```ts
const select = document.querySelector('select')!;
for (const name of player.getPartNames()) {
  if (!name) continue;
  const opt = document.createElement('option');
  opt.value = name;
  // スキンメッシュは不向きな追従先 —— 候補には出すが disabled（淡色）にする。
  opt.disabled = player.isPartSkinnedMesh(name) === true;
  opt.textContent = opt.disabled ? `${name}（スキンメッシュ）` : name;
  select.append(opt);
}
```

**ハードに弾かず、ソフトフィルタに留める**のが要点です。手打ち（やコードからの指定）は Unity / Godot のインスペクタ同様そのまま通し、通した場合は拒否せず注意を促します。`isPartSkinnedMesh()` は同じ判定なので、入力欄の脇に警告を1つ出せば十分です。

`examples/part-follow` デモがまさにこれを行っています。Ringo キャラのスキンパーツ（`hand_r`・`hand_l`・脚・耳・尻尾）がドロップダウンで淡色化され、手打ちで指定すると非ブロッキングの警告が出ます。

## 注意点

- **ターゲットの `visible` はプレイヤーが操作します。** 次の 2 つの場合に自動で非表示化され、条件が解消すると自動で復帰します。
    - パーツ名が現在のアニメーションに存在しない（`onHide` の設定に関係なく常に非表示）
    - パーツが hide のフレームで、かつ `onHide` が `'hide'`
- ただし復帰させるのは**プレイヤー自身が隠した分だけ**です。ユーザーが自分で `visible = false` にしたターゲットは、detach してもそのまま維持されます。
- `isPartHidden()` が返すのは、プレイヤーが最後に描いたフレームでのパーツの hide で、`getPartTransform()` と同じフレームです。**アニメーションの hide キーフレーム**に、[パーツ制御](/ja/customize/part-overrides) の `setPartVisibilityOverride()` による強制非表示（カスケードを含む）を合わせた値になります。呼び出しではフレームを評価しないので、オーバーライドは次に描くフレームから、描画と同時に読み戻せます。
- パーツのワールド行列は hide に関係なく毎フレーム計算されるため、`onHide: 'follow'`（既定）では**非表示のパーツも追従し続けます**。
- パーツ名は、そのプレイヤー自身が再生しているアニメーションのパーツから解決されます。**インスタンスパーツの内部（子アニメーション）のパーツは指定できず**（インスタンスパーツ自体は指定できます）、`getPartQuad()` / `hitTestPart()` からも見えません。
- 同じターゲットを 2 回 `attachToPart()` すると、後の登録が前の登録を置き換えます。
- アニメーションを切り替えるとパーツ名は自動で再解決されるため、登録し直す必要はありません。**同じリグを共有する別の `.ssab` に差し替えた場合も追従は継続します**。
- プレイヤーを `destroy()` すると、全ターゲットが自動で detach されます。ホストが所有するターゲットが破棄されたり、非表示のまま残されたりすることはありません。
- アタッチメントはターゲットへの参照を保持します。ターゲットを先に破棄する場合は、`detach()` してから破棄してください。

## 各ホストからの使い方

- **`<ss-player>` Web Component** — 要素自体は再生系のメソッドだけを持つ薄い皮なので、`el.player`（下層の `SSPlayer`）経由でプル API を呼び出します。詳しくは [WebGL・Web Components で使う](/ja/usage/webgl) を参照してください。
- **RPG ツクール MZ** — パーツトラッキングに対応するプラグインコマンドはありません。スクリプトから `SSPlayer` のインスタンスを取得して `attachToPart()` を呼んでください。詳しくは [RPG ツクール MZ で使う](/ja/usage/rmmz) を参照してください。
- **TyranoScript / TyranoBuilder** — タグは用意していません。

## この機能で扱わないもの

以下は目的が近く混同しやすいのですが、パーツトラッキングの担当範囲ではありません。

| やりたいこと | 正しい方法 |
|---|---|
| パーツ自体の色 / セル / 表示を変える | [パーツ制御（表示 / セル / 色）](/ja/customize/part-overrides) のオーバーライド API を使います |
| パーツをスクリーン座標で追従させる | プレイヤー側の表示変換を自前で合成してください（スクリーン変換まで返す API はありません） |
| インスタンスパーツ配下のパーツに追従させる | 子アニメーションは別のプレイヤーとして動作します。子プレイヤーを取得して、そちらに対して指定してください |
